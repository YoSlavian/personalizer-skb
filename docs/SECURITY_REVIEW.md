## Что проверено и в порядке

- **Зависимости:** npm audit — 0 уязвимостей; 48 Python-пакетов (включая транзитивные) по базе OSV — 0 известных уязвимостей.
- **Аутентификация:** пароли argon2; сессии — случайный токен, в базе только хэш, срок жизни, отзыв; вход в Mini App — проверка подписи
  Telegram initData (HMAC, сравнение за постоянное время, срок 24 ч); ID пользователя из клиентского JSON не используется.
- **CSRF:** cookie-сессии требуют X-CSRF-Token для изменяющих запросов; Mini App работает по Bearer-токену.
- **Доступ к данным (IDOR):** все выборки фильтруются по роли на сервере (`org_scope`): менеджер — свой портфель, клиент — своя компания;
  чужой объект возвращает 404. Черновики заявок видит только автор, внутренние комментарии клиенту не отдаются.
- **Инъекции:** SQL только через параметры SQLAlchemy; в интерфейсе нет `dangerouslySetInnerHTML`; HTML в сообщениях бота экранируется.
- **Заголовки:** CSP, X-Content-Type-Options, Referrer-Policy, HSTS в production, frame-ancestors только Telegram; CORS выключен в production.
- **Вебхук:** секрет X-Telegram-Bot-Api-Secret-Token, повторные update отбрасываются.
- **Контейнер:** приложение работает не от root; секреты передаются переменными окружения Render; `.env` не попадает в образ и репозиторий.

## Остаточные риски (осознанно, для демо)

- **DEMO_MODE на публичном сервере:** любой с ссылкой может войти под демо-ролями и смотреть синтетические данные, создавать заявки,
  задачи, сигналы. Для боевого контура `DEMO_MODE=false`.
- Лимиты запросов хранятся в памяти одного процесса (на одном инстансе Render этого достаточно; для нескольких — Redis).
- Базовые образы Docker закреплены по версии, не по digest.
- Бесплатный тариф Render: база удаляется через 30 дней.
